# 🤖 AI Agent & Decision Engine Architecture

## 1. Overview & Operational Philosophy

In high-stress disaster or off-grid scenarios, generic conversational language models fail because they output verbose, unstructured text, hallucinate non-existent resources, and consume prohibitive GPU/CPU cycles.

**SurvivalOS** implements a **Dual-Engine Hybrid Intelligence Model**:
1. **Local Neural AI (Ollama)**: Evaluates nuances, scenario variations, and open-ended queries when an on-device local model (`qwen2.5`, `qwen3`, `llama3`) is available.
2. **Deterministic Emergency Rule Engine**: Zero-latency, zero-GPU fallback that evaluates mathematical models, inventory levels, and verified handbook protocols when the LLM is uninitialized or the device is low on battery.

---

## 2. Context Synthesis Pipeline

Before submitting a prompt to the AI agent or rule engine, the **Agent Orchestrator** synthesizes local system state into an emergency context payload:

```text
User Input Query
       +
Household Profile (Adults, Children, Elderly, Pets, Geolocation)
       +
Current Water Reserves (Liters, Days of Runway)
       +
Current Food Reserves (Total kcal, Days of Runway)
       +
Active Map Hazards & Safe Zones (Count, Proximity)
       +
Retrieved Handbook Documents (BM25 RAG Matching)
       │
       ▼
[ Agent Orchestrator Context Packet ]
```

## 4. Sandboxed Tool Registry

The AI Agent is strictly limited to invoking predetermined, read-only Python tools:

| Tool Name | Parameters | Purpose |
| :--- | :--- | :--- |
| `calculate_water()` | `adults, children, temp, activity` | Computes daily water quotas and purification doses |
| `calculate_food()` | `household_size, days` | Computes total caloric need and macronutrient targets |
| `get_resource_substitution()` | `missing_item` | Searches substitution catalog for safe alternatives |
| `search_knowledge()` | `query, top_k` | BM25 search over offline markdown handbook |
| `check_inventory()` | `category_filter` | Audits current stock counts and expiration flags |
| `find_saved_markers()` | `marker_type, status` | Queries local geospatial database for safe zones |
| `calculate_readiness()` | `None` | Evaluates overall 0–100 preparedness score |

---

## 5. Fallback Mechanics & Resilience

1. When a query is received, the orchestrator pings `http://localhost:11434/api/tags` with a 1.5-second timeout.
2. If Ollama responds with an active model, the structured system prompt is executed.
3. If Ollama fails, times out, or returns invalid JSON, the orchestrator silently catches the error and executes the `DecisionEngine` fallback within **<5 milliseconds**.
4. The user always receives actionable, life-saving triage steps without infinite loading spinners or crash screens.
